# 已知问题与后续规划

> 主动交代短板。这份文件的存在本身是"目标给人用"这条要求的一部分——
> 与其让审核人自己发现问题，不如我先说清哪里不行。

---

## 一、功能缺失（明确没做）

| 缺失 | 影响 | 后续 |
|---|---|---|
| **批量队列** | 一次只能转一个文件。真实场景里用户往往有十几个文件 | 高优先级。需要引入任务队列 + 状态机 + 并发控制 |
| **九宫格 / 时间轴缩略图** | 只能看一个时间点的画面，找片头/选片段不方便 | 中优先级。`fps=1/8,tile=3x3` 一次解码出 9 帧，成本可控 |
| **安装包** | 分发是 zip 解压，没有开始菜单项和卸载入口 | 低优先级。Inno Setup 约 40 行脚本 |
| **字幕 / 音轨处理** | 只能转视频流和音频流，不能烧字幕、不能选音轨 | 中优先级 |
| **视频剪辑（截取片段）** | 不能只转前 30 秒 | 低优先级，`-ss` / `-to` 即可 |
| **深色主题** | 目前只有浅色 QSS | 低优先级，改一份 QSS 变量即可 |

## 二、精度与能力边界

| 问题 | 现状 | 说明 |
|---|---|---|
| **目标体积不精确** | 单遍编码 + `maxrate`/`bufsize` 约束，误差约 ±10%（实测 59 MB → 约 17 MB，目标 20 MB） | 要做到 ±2% 需要两遍编码，耗时翻倍。当前取舍是"够用且快" |
| **画质主界面只有 4 个档位** | 极佳 / 高 / 标准 / 省体积 对应 CRF 20 / 23 / 26 / 30；「高级设置」里可以直接填 18~35 任意值，且与档位双向同步 | 主界面尺度的取舍：档位是给"不知道该选什么"的人用的，数值是给"知道"的人留着。两者不是替代关系 |
| **硬件编码默认不可用** | 开发机 RTX 5060 + 驱动 573.24，低于 ffmpeg 9.0.1 要求的 610.00，实测降级到 libx264 | 这是**驱动版本问题不是代码问题**。升级驱动到 610+ 即自动启用 NVENC，代码路径已实现并测试过回退逻辑 |
| **只支持 H.264 输出** | 没有 H.265 / AV1 / VP9 选项 | H.265 在体积上有明显优势，但兼容性和硬件支持参差，本期没做 |
| **只支持 MP4/MKV/MOV/WEBM** | 其它容器会回落到 mp4 | — |
| **不做画质增强** | 只有转码，没有超分、降噪、锐化 | 刻意不做：这类效果难以量化验证，容易变成"看起来厉害但没法证明"的功能 |

## 三、稳定性

| 问题 | 现状 | 缓解 |
|---|---|---|
| **没有进度持久化** | 转到一半关掉程序，任务就没了 | 转码产物会留在磁盘（取消时 ffmpeg 会正常收尾，产物可播放） |
| **超长视频的 ETA 抖动** | 用了 7 次采样的中位数，但码率突变的片段仍会跳 | 属于观感问题，不影响功能 |
| **没有崩溃恢复** | 异常退出后不记住上次状态 | — |
| **单实例** | 可以开多个窗口同时转码，互相不知道 | 影响不大，未处理 |
| **任务栏进度未能自证** | 代码已实现（ctypes 调 ITaskbarList3），但本机开发环境的 COM 上下文里该接口返回 `E_NOINTERFACE`，**没能验证成功** | 失败是静默降级的：拿不到接口就什么都不做，不影响转码。日志里会留一行 INFO。是否有进度条取决于真实桌面会话，请在自测时确认（MANUAL_TEST 第 19 项） |

## 二·五、分发体积

| 项 | 数值 | 说明 |
|---|---|---|
| Release zip | 约 155 MB | 解压后约 400 MB |
| 其中 ffmpeg + ffprobe | 各 138 MB | 手头这个 9.0.1 构建未 strip |

「双击就能用」和「体积小」这两件事在本次是冲突的，我选了前者：审核人第一次打开时
不该先去装 ffmpeg。缓解手段都写在这里——把 `vendor/` 换成 stripped 构建（约 60 MB/个）
或改用 `--onefile` + 首次解压，能把包体砍到 60 MB 内。这次没做，是因为验证过的东西不想在
交付前动。

## 四、测试覆盖的空白

已覆盖（116 个测试，其中 16 个是界面冒烟）：
- `ffprobe` JSON 解析、`ffmpeg -i` 兜底解析
- 参数拼装、编码器回退、音轨缺失、缩放不放大、目标体积边界
- 进度解析（含 `out_time_ms` 单位坑、`N/A`、越界、ETA）
- 档位映射（画质/音质数值 ↔ 用户档位，越界与平局规则）
- 本地规则引擎（关键词命中、参数合法域、说明文案不得含技术黑话）
- 顾问面板的行为契约（空态给引导不给控件、说明条数、置信度不得出现）
- 两层参数的双向绑定（档位 ↔ CRF / 码率，精调值优先）

**没覆盖到、只能人工验证的**：
- 真实转码的正确性（画面是否正常、音画是否同步）
- 中途取消后产物是否真的可播放
- 无 GPU 机器上的行为
- 中文 + 空格路径
- 干净 Windows 环境双击 exe

这些在 `docs/SESSION_LOG.md` 里有手工验证记录，但没有自动化。
要补的话，取消路径可以用 `subprocess` 起 exe、跑 3 秒、杀进程、再用 `ffprobe` 校验产物完整性。

## 五、已知的"非问题"

以下几件事看起来像问题，但是刻意为之：

1. **界面没有动画**。两天工期内自绘控件和动画是自杀式投资，QSS 静态样式性价比最高。
2. **没有设置页**。API Key 走环境变量或 `%APPDATA%\VideoBox\config.json`，
   因为目标用户（审核人）大概率不会配，配了也是降级路径能兜住。
3. **左栏不做文件列表**。把空间让给大缩略图——一次转一个文件，列表本身没有用武之地，
   而缩略图是用户确认"拖对了没有"最快的方式。
4. **没有登录 / 会员 / 在线客服**。这是一个本地工具：不联网也能完整跑，没有账号体系、
   没有付费墙、没有需要找客服才能解决的问题。多一个登录页只会多一道门。
   详细理由写在 `docs/DECISIONS.md` 第 8 节。
